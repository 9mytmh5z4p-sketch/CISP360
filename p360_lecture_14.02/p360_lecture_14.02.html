new and delete

How Can a Program Request Memory While It Is Running?

  • What if the amount of data is known only after the program starts?
  • What if the data must remain alive beyond the block that creates it?

Slides 4–19 [Graphic suggestion: a program requesting a new labeled block from a pool of available memory.]

Why This Matters

  • Runtime decisions can determine whether and when an object is needed.
  • Some data must remain alive after the creating function returns.
  • Automatic storage alone cannot express every required lifetime.

Automatic Storage Has a Boundary

#include <iostream>
using namespace std;

void showScore();

int main() {
    showScore();
    return 0;
}

void showScore() {
    int score = 92;
    cout << score << "\n";
} // score's lifetime ends here

[Graphic suggestion: a stack frame appearing for showScore and disappearing at the closing brace.]

Dynamic Storage Has a Different Lifetime

int* score = new int{92};

// The allocation remains alive until delete.
cout << *score << "\n";

delete score;
score = nullptr;
  • The pointer has scope; the allocation has a separately controlled lifetime.

Allocating One Value

int* score = new int;
  • new int reserves enough dynamic storage for one int.
  • new returns the address of that storage.
  • score stores the returned address.

[Graphic suggestion: stack variable score containing an arrow to one int-sized heap block.]

Initializing During Allocation

int* a = new int;      // indeterminate value
int* b = new int();    // value-initialized to 0
int* c = new int{42};  // initialized to 42
  • Braced initialization makes the intended starting value explicit.

Using the Allocation

int* score = new int{92};

cout << *score << "\n";
*score = 97;
cout << *score << "\n";
  • Dereferencing accesses the dynamically stored object.

A Complete Scalar Example

#include <iostream>
using namespace std;

int main() {
    double* temperature = new double{98.6};

    cout << "Temperature: " << *temperature << "\n";
    *temperature = 101.3;
    cout << "Updated: " << *temperature << "\n";

    delete temperature;
    temperature = nullptr;
    return 0;
}

What Does delete Do?

  • delete ends the dynamically allocated object’s lifetime.
  • The storage becomes available for reuse.
  • The pointer variable still exists and still contains the old address.
delete temperature;
temperature = nullptr;

Following the Addresses

Moment Pointer Dynamic object
After new Holds allocated address Alive
After delete Still holds old address Dead
After nullptr assignment Holds no address Dead

Allocation Inside a Function

#include <iostream>
using namespace std;

double* readTemperature();

int main() {
    double* value = readTemperature();
    cout << *value << "\n";
    delete value;
    value = nullptr;
    return 0;
}

double* readTemperature() {
    double* result = new double;
    cin >> *result;
    return result;
}

Who Owns the Allocation?

  • readTemperature creates the allocation.
  • Returning the pointer transfers cleanup responsibility to main.
  • The owner must eventually call the matching deallocation operation.

[Graphic suggestion: ownership label moving from readTemperature’s result pointer to main’s value pointer.]

The Scalar Lifetime Pattern

Step C++ operation
Allocate and initialize int* value = new int{5};
Access the object cout << *value;
Release the object delete value;
Mark the pointer empty value = nullptr;

The Ownership Contract

For every dynamic allocation, identify:

  • The pointer that owns the allocation
  • Any pointers that merely borrow access
  • The exact point where the owner releases it

Summary

  • new creates dynamic storage whose lifetime is controlled explicitly.
  • delete releases one scalar allocation.
  • Runtime flexibility comes with an ownership and cleanup obligation.

Pseudodynamic Memory

Fixed Storage, Variable Use?

  • Can a fixed array use a length chosen when the program starts?
  • What remains fixed, and what is allowed to change?

Slides 20–38 Pseudodynamic memory is course terminology, not a standard C++ term.

Two Flavors

  • Stack flavor: a fixed-capacity array is declared as a local variable.
  • Heap flavor: an array is allocated on the heap after the program knows the requested length.

Both patterns separate physical storage from the logical length the program is currently using.

Capacity Versus Logical Length

  • Capacity is the number of elements physically reserved.
  • Logical length is the number of elements currently treated as valid.
  • The logical length may change, but it must stay between 0 and CAPACITY.

[Graphic suggestion: ten array cells with six marked active and four marked unused.]

Three Meanings of Size

Term Meaning Example
Capacity Physical slots in the array 100
Requested length Amount the user asks to use 8
Logical length Valid elements after validation 8

The requested length becomes the logical length only when it fits the capacity.

The Stack Pattern

const int CAPACITY = 100;
double sales[CAPACITY] = {};
int length;

cout << "Number of sales values: ";
cin >> length;

The allocation is fixed at compile time. The program chooses how much of it to use at runtime.

Steps for the Stack Pattern

  1. Validate the requested length.
  2. Initialize only active elements.

The next two slides show the two required steps before the array is safe to process.

Validate the Requested Length

while (length < 0 || length > CAPACITY)
{
    cout << "Enter a length from 0 to " << CAPACITY << ": ";
    cin >> length;
}

Boundary: valid indexes will be 0 through length - 1.

Initialize Only Active Elements

for (int index = 0; index < length; index++)
{
    cout << "Sale " << index + 1 << ": ";
    cin >> sales[index];
}

The loop follows logical length, not physical capacity.

Display Only Active Elements

for (int index = 0; index < length; index++)
{
    cout << sales[index] << '\n';
}

Predict: if length is 4, how many values appear when capacity is 100?

Complete Fixed-Capacity Program

#include <iostream>
using namespace std;

int main()
{
    const int CAPACITY = 10;
    int scores[CAPACITY] = {};
    int length;

    cout << "How many scores? ";
    cin >> length;
    while (length < 0 || length > CAPACITY)
    {
        cout << "Enter 0 through " << CAPACITY << ": ";
        cin >> length;
    }

    for (int i = 0; i < length; i++)
    {
        cout << "Score " << i + 1 << ": ";
        cin >> scores[i];
    }

    for (int i = 0; i < length; i++)
        cout << scores[i] << ' ';
    cout << '\n';
    return 0;
}

Make the Contract Visible

void display(const int values[], int length);
double average(const int values[], int length);
  • The array parameter provides access to the storage.
  • length identifies the valid range.
  • Capacity is needed only by operations that may add elements.

Compute with Active Elements

#include <iostream>
using namespace std;

double average(const int values[], int length);

int main()
{
    const int CAPACITY = 8;
    int values[CAPACITY] = {12, 18, 24, 30};
    int length = 4;

    cout << average(values, length) << '\n';
    return 0;
}

double average(const int values[], int length)
{
    if (length == 0)
        return 0.0;

    int total = 0;
    for (int i = 0; i < length; i++)
        total += values[i];
    return static_cast<double>(total) / length;
}

Change Use, Not Allocation

length = 3;  // Three elements are logically active
length = 6;  // Six elements are logically active

Changing length does not create or destroy array cells. Newly activated cells must receive valid values before use.

Add at the Logical End

bool append(int values[], int& length, int capacity, int value)
{
    if (length == capacity)
        return false;

    values[length] = value;
    length++;
    return true;
}

Invariant: 0 <= length && length <= capacity.

Remove the Last Element

bool removeLast(int& length)
{
    if (length == 0)
        return false;

    length--;
    return true;
}

The stored bits may remain, but that cell is no longer logically valid.

Trace the Boundary

const int CAPACITY = 5;
int values[CAPACITY] = {4, 7, 9};
int length = 3;

append(values, length, CAPACITY, 12);
removeLast(length);

Predict: after both calls, what is length, and which indexes are valid?

[Graphic suggestion: before/after array cells with a bold boundary at length.]

The Capacity Wall

  • Appending works only while unused physical slots remain.
  • A request beyond capacity cannot be satisfied by changing logical length.
  • Runtime allocation removes the predetermined capacity, but adds ownership duties.

Summary

  • Pseudodynamic memory uses fixed capacity with a runtime logical length.
  • Every operation preserves 0 <= length <= capacity and accesses only valid indexes.

Pseudodynamic Memory - Heap

When Fixed Capacity Is Not Enough

  • What if the program should ask for the array length when it runs?
  • Heap allocation removes the compile-time capacity wall, but the allocation still has a fixed length once created.

Slides 39–62

Two Flavors

  • Stack flavor: a fixed-capacity array is declared as a local variable.
  • Heap flavor: an array is allocated on the heap after the program knows the requested length.

The heap flavor is more flexible at program start, but it introduces ownership and cleanup responsibilities.

From One Value to Many

int* oneScore = new int;
int* manyScores = new int[count];

The second allocation reserves count contiguous int elements on the heap.

[Graphic suggestion: two stack pointer variables, one pointing to a scalar heap cell and one to an array block.]

Scalar Versus Array Allocation

Allocation Access Matching release
new int *pointer delete pointer
new int[count] pointer[index] delete[] pointer

The bracket form is part of the allocation contract.

Why the Brackets Matter

int* value = new int;
int* values = new int[10];

delete value;
delete[] values;

Mixing scalar and array release forms causes undefined behavior.

Pointer on the Stack, Array on the Heap

  • The pointer variable has its own storage and scope.
  • The heap array remains allocated until its owner releases it.
  • Losing the pointer does not release the array.

[Graphic suggestion: stack frame containing values and length, with an arrow to a heap block. Label the pointer and allocation lifetimes separately.]

Validate Before Allocating

cout << "How many scores? ";
cin >> length;

while (length < 0)
{
    cout << "Enter zero or more: ";
    cin >> length;
}

No allocation should occur until the requested length satisfies the program contract.

Zero Elements Means No Allocation

int* scores = nullptr;

if (length > 0)
    scores = new int[length];

nullptr clearly represents “no array.” Both delete[] nullptr and guarded traversal are safe.

Allocate the Requested Length

int* scores = new int[length];

for (int index = 0; index < length; index++)
    scores[index] = 0;

The allocated length is fixed for the lifetime of this allocation.

Read and Display Values

for (int i = 0; i < length; i++)
{
    cout << "Score " << i + 1 << ": ";
    cin >> scores[i];
}

for (int i = 0; i < length; i++)
    cout << scores[i] << ' ';
cout << '\n';

Boundary: every subscript must remain below length.

Complete Heap-Allocated Array Program

#include <iostream>
using namespace std;

int main()
{
    int length;
    cout << "How many temperatures? ";
    cin >> length;

    if (length <= 0)
        return 0;

    double* temperatures = new double[length];
    for (int i = 0; i < length; i++)
    {
        cout << "Temperature " << i + 1 << ": ";
        cin >> temperatures[i];
    }

    for (int i = 0; i < length; i++)
        cout << temperatures[i] << '\n';

    delete[] temperatures;
    temperatures = nullptr;
    return 0;
}

Three Meanings of Size

  • Requested length: input proposed by the user.
  • Allocated length: elements reserved by the successful new[] expression.
  • Logical length: elements the program currently treats as valid.

In the heap pseudodynamic pattern, these values usually become the same after validation.

Pass Pointer and Length Together

void display(const int values[], int length);
double average(const int values[], int length);

The pointer carries an address. The length carries the boundary contract.

Compute Through a Pointer

#include <iostream>
using namespace std;

double average(const int values[], int length);

int main()
{
    int length = 4;
    int* values = new int[length]{10, 20, 30, 40};
    cout << average(values, length) << '\n';
    delete[] values;
    values = nullptr;
    return 0;
}

double average(const int values[], int length)
{
    if (length == 0)
        return 0.0;

    int total = 0;
    for (int i = 0; i < length; i++)
        total += values[i];
    return static_cast<double>(total) / length;
}

Where Are the Bounds?

  • A raw pointer does not know the array length.
  • values[length] is already one element beyond the allocation.
  • An out-of-bounds read or write causes undefined behavior.

One Element Too Far

int* values = new int[3]{4, 8, 12};

cout << values[2] << '\n';  // Last valid element
cout << values[3] << '\n';  // Outside the allocation

delete[] values;

Predict: is any particular output guaranteed for the second statement?

Preserve the Base Address

int* values = new int[4]{3, 6, 9, 12};
int* cursor = values;

cursor++;
cout << *cursor << '\n';

delete[] values;
values = nullptr;

The owning pointer retains the address returned by new[].

Traverse Without Losing Ownership

int* cursor = values;
int* end = values + length;

while (cursor != end)
{
    cout << *cursor << '\n';
    cursor++;
}

cursor moves; values continues to own the base address.

Losing the Only Pointer

int* values = new int[10];
values = nullptr;

The allocation still exists, but its address is gone. It can no longer be released.

[Graphic suggestion: heap block with its ownership arrow removed while the pointer now holds nullptr.]

Cleanup Before Every Return

int* values = new int[length];

if (!readValues(values, length))
{
    delete[] values;
    values = nullptr;
    return 1;
}

delete[] values;
values = nullptr;
return 0;

Each exit path must honor the ownership invariant.

One Cleanup Path

int result = 0;
int* values = new int[length];

if (!readValues(values, length))
    result = 1;
else
    display(values, length);

delete[] values;
values = nullptr;
return result;

One release point makes manual ownership easier to audit.

Still Pseudodynamic

  • The array length can be chosen at runtime.
  • Once the heap block is allocated, that block does not change size.
  • To change the size, the program must allocate a different block and move the data it wants to keep.

Summary

  • Heap pseudodynamic memory uses new[] to choose array length at runtime.
  • The allocation has a fixed size until it is released, so ownership and bounds must be tracked explicitly.

Dynamic Memory

When the Data Changes the Size

  • Heap pseudodynamic memory chooses a size when the allocation is created.
  • Truly dynamic memory changes allocation size as the program’s data changes.

The program does not ask the user for a new length each time. The data operation itself creates the need for a different array size.

Slides 63–80 This topic is organized around rdaa.cpp, the real dynamically allocated array example.

rdaa.cpp

// rdaa.cpp  -- real dynamically allocated array
#include <iostream>
using namespace std;

int main(){     // build the initial array
    int* pInt = nullptr;
    int size = 1;

    pInt = new int[size];
    pInt[0] = 10;

    for (int i = 0; i < size; i++)
    cout << pInt[i] << "  ";
    cout << endl;

// increase by 1
    int* pTemp = nullptr;
    size++;
    pTemp = new int[size];

    pTemp[0] = pInt[0];
    pTemp[1] = 20;

    delete[] pInt;
    pInt = pTemp;
    pTemp = nullptr;

    for (int i = 0; i < size; i++)
    cout << pInt[i] << "  ";
    cout << endl;

    // decrease by 1 from the right
//    int* pTemp = nullptr;
    size--;
    pTemp = new int[size];
    pTemp[0] = pInt[0];

    delete[] pInt;
    pInt = pTemp;
    pTemp = nullptr;

    for (int i = 0; i < size; i++)
    cout << pInt[i] << "  ";
    cout << endl;

    return 0;
}

This file is the complete example that the next slides dissect.

The rdaa.cpp Story

  1. Build an array with one value.
  2. Add a second value by creating a larger array.
  3. Remove a value by creating a smaller array.

Each size change is really a new allocation plus a transfer of the values that still matter.

Start With One Element

int* pInt = nullptr;
int size = 1;

pInt = new int[size];
pInt[0] = 10;

At this moment, pInt owns a heap array with exactly one element.

Grow in Response to New Data

int* pTemp = nullptr;
size++;
pTemp = new int[size];

pTemp[0] = pInt[0];
pTemp[1] = 20;

The new value 20 requires a larger array. The old value is copied before ownership changes.

Transfer Ownership After Copy

delete[] pInt;
pInt = pTemp;
pTemp = nullptr;

pInt becomes the owner of the larger array only after the old array has been released.

Shrink When Data Is Removed

size--;
pTemp = new int[size];
pTemp[0] = pInt[0];

delete[] pInt;
pInt = pTemp;
pTemp = nullptr;

Removing data from the right means the retained values fit in a smaller allocation.

Finish the Ownership Contract

delete[] pInt;
pInt = nullptr;

After the final print, pInt still owns a heap allocation. The program should release that last array before it ends.

Trace the Size Changes

Moment Owner Size Stored values
Start pInt 1 10
After grow pInt 2 10 20
After shrink pInt 1 10

Predict: what would print after each stage?

Why Resizing Needs a New Array

  • An existing allocation cannot grow or shrink in place through C++ syntax.
  • Resizing means allocating a different block and preserving the desired values.
  • Ownership transfers only after the copy succeeds.

The Resize Algorithm

  1. Decide the new length from the data operation.
  2. Allocate a temporary array.
  3. Copy the elements that still belong.
  4. Release the old array.
  5. Point the owner to the new array.
  6. Update the tracked length.

How Many Elements Should Be Copied?

int copyCount = oldLength;
if (newLength < oldLength)
    copyCount = newLength;

The general rule is min(oldLength, newLength).

Add One Element

void append(int*& values, int& length, int value)
{
    int* temporary = new int[length + 1];

    for (int i = 0; i < length; i++)
        temporary[i] = values[i];

    temporary[length] = value;
    delete[] values;
    values = temporary;
    temporary = nullptr;
    length++;
}

Both pointer and length use reference parameters because the function changes the caller’s state.

Remove the Last Element

bool removeLast(int*& values, int& length)
{
    if (length == 0)
        return false;

    int* temporary = nullptr;
    if (length > 1)
        temporary = new int[length - 1];

    for (int i = 0; i < length - 1; i++)
        temporary[i] = values[i];

    delete[] values;
    values = temporary;
    length--;
    return true;
}

Resize to Any Length

void resize(int*& values, int& length, int newLength)
{
    if (newLength < 0 || newLength == length)
        return;

    int* temporary = nullptr;
    if (newLength > 0)
        temporary = new int[newLength]{};

    int copyCount = length;
    if (newLength < length)
        copyCount = newLength;

    for (int i = 0; i < copyCount; i++)
        temporary[i] = values[i];

    delete[] values;
    values = temporary;
    length = newLength;
}

The Cost of Resizing

  • Allocating a new block requires work proportional to the requested storage.
  • Copying retained elements takes O(N) time.
  • Growing by one element repeatedly can perform many unnecessary copies.

Summary

  • Dynamic memory changes the allocation when the program’s data requires a different size.
  • A resize is allocate, copy, release, transfer ownership, and update length.

Key Takeaways

  • Dynamic allocation separates an object’s lifetime from the scope that creates it.
  • Pseudodynamic storage separates fixed capacity from runtime logical length.
  • Heap arrays use new[] and the matching delete[]; a raw heap array does not track its length or check its bounds.
  • Dynamic memory changes allocation size by allocating, copying, releasing, transferring ownership, and updating length.

new and delete: Good Practices

  • Initialize allocations immediately when possible.
  • Preserve one clear owning pointer for each scalar allocation.
  • Place the matching release near the end of the owner’s responsibility.

new and delete: Common Mistakes

  • Calling delete more than once for the same allocation
  • Forgetting cleanup on an early return
  • Treating the pointer’s scope as the allocation’s lifetime

  • Match new[] with delete[].

Pseudodynamic Memory - Heap: More Examples

int* clone(const int source[], int length)
{
    if (length == 0)
        return nullptr;

    int* copy = new int[length];
    for (int i = 0; i < length; i++)
        copy[i] = source[i];
    return copy;
}

The caller receives ownership of the returned allocation.

Dynamic Memory: Good Practices

  • Keep old and new arrays alive during copying.
  • Transfer ownership only after the retained values have been copied.
  • Update the stored length after the owning pointer points to the new allocation.

Dynamic Memory: Common Mistakes

  • Updating length before the copy uses the old boundary
  • Deleting the old array before copying retained values
  • Forgetting that repeated one-element growth performs repeated copying
